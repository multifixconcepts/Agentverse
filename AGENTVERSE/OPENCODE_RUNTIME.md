# OPENCODE RUNTIME — Org → OpenCode Mapping

How Agentverse maps onto the OpenCode runtime at `/home/coder/project`.

## 1. Layout

```
/home/coder/project/
├── opencode.jsonc            # project OpenCode config (MCP, permissions, skills)
├── AGENTVERSE/               # control planes
│   ├── AGENTVERSE.md         # ontology & operating model
│   ├── AGENT_REGISTRY.json   # canonical 70-agent roster
│   ├── COHESION_MATRIX.md    # control plane #1 (gates, RACI, cohesion)
│   ├── MEMORY_INDEX.md       # control plane #2a
│   ├── KNOWLEDGE_BASE.md     # control plane #2b
│   ├── USER_GUIDE.md         # user handbook & operating manual
│   └── OPENCODE_RUNTIME.md   # this file
├── .opencode/
│   ├── agents/               # 70 subagent definitions (generated)
│   ├── skills/               # shared skills (delegate, review-gate, scholapro, mcp-ops)
│   ├── command/summon.md     # /summon → Summoner with full gate-chain execution
│   └── (plugins/ optional)
├── _tools/gen-agents.js      # roster → agents + registry generator
└── scholapro/                # the product (ScholaPro / RosarioSIS 12.5 fork)
```

## 2. Agent mapping

- **Summoner** = the primary agent (`default_agent`). Users talk to Summoner only.
- Every other roster entry = `mode: subagent` file under `.opencode/agents/<id>.md` (generated by `_tools/gen-agents.js`).
- `AGENT_REGISTRY.json` is the source of truth; regenerate with:
  `/usr/lib/code-server/lib/node _tools/gen-agents.js`
- Subagents are invoked via the task/delegation workflow (skill: `delegate`).

## 2b. Commands

- `/summon <request>` → runs the Summoner with the given request (`.opencode/command/summon.md`), which triages, delegates, and drives the G0–G6 gate chain. This is the recommended user entry point.

**Secret policy:** portainer/n8n/secure-command contain credentials — do **not** hardcode them in committed `opencode.jsonc`; provide via environment (`{env:VAR}` interpolation) or keep in `.memory/` + host config only.

## 4. Permissions

- Project config `permission` defaults: read/glob/grep allow; bash ask; edit allow for RW/P tier agents.
- Production tier agents (host-ops-specialist, docker-ops, portainer-ops, db-admin, release-custodian, security ops) carry `bash: allow` + must log every action in the ticket.
- Reviewers/auditors are read-only (frontmatter `permission.edit: deny`).

## 5. Skills

`.opencode/skills/<name>/SKILL.md`:
- `delegate` — Summoner delegation workflow (triage → route → evidence).
- `review-gate` — gate chain protocol (G1–G6, fast-path waivers).
- `scholapro` — product conventions: PHP/JS/CSS, modules, verification via php:8.1 container & node.
- `mcp-ops` — using recovered MCP servers.

## 6. Restart note

OpenCode loads config once at startup. **Quit and restart opencode** after adding/editing `opencode.jsonc`, agents, skills, or plugins for changes to take effect.
